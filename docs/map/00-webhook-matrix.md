# 00 — Consolidated webhook trigger matrix (Shaype → client)

Purpose: one table per notification stream answering, for **every** event type in `notification-webhooks.json`, *which B2B operation, staging mock generator or external event makes the local implementation emit it*, and where the per-domain maps disagree.

Sources and labels:

- `[spec]` = `notification-webhooks.json` (every enum below re-verified with `jq` at write time; see Appendix). `[spec:b2b]` = `b2b-operations-api.json` / `ops.json`.
- `[docs:<slug>]` = `developer.shaype.com/docs/<slug>.md`.
- `[map:<key>]` = the per-domain map that makes the claim (`webhooks`, `customers`, `accounts`, `cards`, `transactions-holds`, `utilities`, `payid-npp`, `bpay`, `de-dd-scheduled`, `groups-stacks`, `kyc`, `payto`).
- `[inferred]` = not stated by any source. `[decision]` = recommended default for the local implementation.

Method: `map/webhooks.md` read in full; the other 11 maps searched with `grep -n -i -E 'webhook|notification|event'` (+3 lines of context) only.

## 10. Recommended defaults — summary of every `[decision]` above

| area | default |
|---|---|
| Streams emitted | v0 `/notification` always; v1 `/notification` only if Batch or Perks API implemented; `/sms` never; `/email` behind `webhooks.emailStream` (off) |
| Envelope | `customerHayId` = owner of the affected resource (sender for outbound, recipient for inbound, creditor/debtor holder for PayTo sides); fresh `idempotencyKey` per event (retries reuse it); `actionOwner` `CLIENT` for events caused by a B2B call, `PLATFORM` for rails / mocks / schedulers; `productId` = account's product; `cardHayId` on card events; `firebaseDeviceToken` omitted |
