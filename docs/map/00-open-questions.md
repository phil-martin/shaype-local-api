# Open questions and gaps — consolidated across the 14 domain maps

**Scope.** Every item in the `## 7. Open questions` section of the 12 domain maps, `## 11` of `crosscutting.md` and `## 6` of `webhooks.md` (317 raw items), deduplicated into 154 decision points, grouped by theme, each with a recommended default for the local test double and a priority. Section 12 lists documentation pages from `llms.txt` that no map cites; section 13 lists positions on which two maps disagree with each other.

**Sources.** `[spec]` = `b2b-operations-api.json` (169 operations per `ops.json`), `[webhook-spec]` = `notification-webhooks.json`, `[docs:<slug>]` = `https://developer.shaype.com/<slug>.md`, `[map:<key>#n]` = item *n* of that map's open-questions section (webhooks uses `Q n`), `[inferred]` = reasoning not backed by a source, `[decision]` = the recommended default for the local double. Every enum printed below was read with `jq` from the spec named beside it.

**Priority.** `P1` = the happy path (create customer → account → card → post transaction → webhook) or a cross-cutting convention every test touches cannot be built without deciding it. `P2` = a secondary domain flow or an edge tests will hit. `P3` = cosmetic, unlikely to be asserted, or no B2B operation reaches it.

**Convention for `[decision]` entries.** "Config" means a startup option of the local double; "test hook" means a route under `/_test/*` that production does not have. Defaults are chosen to (a) follow the spec where spec and docs disagree unless the docs describe observed wire behaviour, (b) prefer the superset (emit more webhooks, accept more inputs) so tests can ignore what they do not need, and (c) never require a wall clock to advance.
