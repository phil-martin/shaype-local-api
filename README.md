A cleanroom, local re-implementation of the [Shaype B2B Operations API](https://developer.shaype.com/openapi/b2b-operations-api.json) for end-to-end testing of code that integrates with Shaype, on a developer machine. Stateful (customers, accounts, cards, transactions, holds, PayIDs, mandates, …), backed by SQLite (in-memory or file), with Cognito-style client-credentials auth and outbound webhook notifications. Not affiliated with Shaype. Not for production use.

## Quick start

```sh
npm install
npm run dev -- --port 8080 --webhook-url http://localhost:3000
# token:  POST http://127.0.0.1:8080/oauth2/token  (grant_type=client_credentials, client_id=local-client, client_secret=local-secret)
# health: GET  http://127.0.0.1:8080/_admin/health
```

`npm run dev -- --help` lists every flag and its `SHAYPE_LOCAL_*` environment variable.

## How it works

- `spec/` holds the vendored OpenAPI files; `npm run gen` turns them into a routing table plus request/response JSON Schemas, so every one of the 169 operations validates input and serialises output exactly as the spec declares.
- Each domain under `src/domains/` implements its operations against SQLite and emits domain events; the webhook dispatcher turns those into Shaype-shaped notifications and POSTs them to `<webhook-url>/api/hay/v0/communications/notification` (retrying on 401/403/429/5xx like the real platform).
- Operations that are not implemented yet (or are stub-only by design: Perks, FX, Liquidity, Click to Pay, Tokens, MCCs) answer with deterministic, spec-shaped example data and an `x-shaype-local-stub` header.
- `/_admin/*` gives tests control: reset state, move the virtual clock, list/clear/redeliver notifications, wait for async work to settle.

Design spec: `docs/superpowers/specs/2026-09-24-shaype-local-api-design.md`. Verified per-domain API maps: `docs/map/`.
